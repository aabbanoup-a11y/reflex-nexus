## 1. القرار المنتجّي النهائي

AbanoubAI منتج واحد يعمل عبر واجهتين مستقلتين، وليس موقعًا يفتحه تطبيق Android:

1. **Web App / PWA:** تطبيق ويب مستقل قابل للتثبيت من المتصفح على الأجهزة المدعومة، يعمل في وضع standalone بعد التثبيت، وله دورة إصدار مستقلة.
2. **Android App:** تطبيق Android أصلي مستقل بـKotlin وJetpack Compose، لا يستخدم WebView لعرض تطبيق الويب ولا يفتح صفحة الويب باعتبارها واجهته.
3. **Shared Backend:** حساب ومصادقة وخدمات API وبيانات وذاكرة ومهام مشتركة، مع واجهة API موثقة وآمنة. استقلال الواجهتين لا يعني نسخ قاعدة البيانات أو منطق الصلاحيات.

تُحدّث الواجهتان بالتوازي من خلال عقود API ونظام تصميم مشترك؛ ولا يشترط أن تنشرا في اللحظة نفسها. لا تعتمد إحداهما على فتح الأخرى كي تعمل.

## 2. قرارات التصميم المعتمدة من المستخدم

- الاتجاه: **Premium Executive**.
- الألوان: أسود/فحمي مع ذهبي معدني راقٍ، ووضعان Dark وLight.
- العلامة: حرف **A** واحد واضح وقابل للتمييز كأيقونة Launcher، بلا نصوص صغيرة أو رموز روبوت/دماغ نمطية.
- اللغة في إصدار 25 نوفمبر: العربية أولًا، RTL كاملًا. تُبنى الرموز والخطوط والتخطيطات بحيث لا تمنع إضافة الإنجليزية LTR لاحقًا.
- هيكل التنقل: **وجهة رئيسية واحدة (Home / Workspace)**، وجميع الوجهات الأخرى داخل Sidebar.
- الويب على الشاشات الواسعة: Sidebar ثابت قابل للطي.
- الويب على الهاتف: Sidebar منزلق (Drawer).
- Android على الهاتف: Modal Navigation Drawer منزلق من الحافة، ولا يوجد Bottom Navigation.
- Android على الشاشات الكبيرة: Drawer ثابت أو قابل للطي بحسب المساحة.
- كثافة الواجهة: غنية ومنظمة، لا Minimal فارغ ولا ازدحام؛ بطاقات متعددة المستويات، رسوم دقيقة، مؤشرات واضحة، مساحات تنفس، وتأثيرات ذهبية محدودة.
- ممنوع استخدام Figma. أدوات التصميم: Canva للأصول/دليل الهوية، ومخرجات التصميم المرئية المعتمدة كمرجع تنفيذي؛ التنفيذ الفعلي في الكود والمراجعة على الأجهزة.

## 3. خريطة المعلومات والتنقل

### الوجهة الرئيسية
**الرئيسية / مساحة العمل** هي الشاشة الوحيدة الافتراضية عند فتح التطبيق، وتحتوي على:
- تحية وسياق مختصر لليوم.
- ملخص مهام اليوم والتقدم الحقيقي (لا أرقام تجريبية).
- مدخل المساعد الذكي / بدء مهمة.
- المهام القادمة والتنبيهات ذات الصلة.
- نشاط حديث وحالة التكاملات.
- ملخص ذاكرة/معرفة عندما توجد بيانات فعلية.
- حالات واضحة للتحميل والفراغ والخطأ وانقطاع الاتصال.

### عناصر Sidebar

2. المساعد الذكي
3. الوكلاء
4. المهام والتنفيذ
5. التخطيط والجدولة

تُجمع العناصر المتقاربة في مجموعات واضحة مع فواصل وعناوين صغيرة. تُخفى العناصر التي لا تنطبق على المستخدم أو لا يملك صلاحيتها، لكن لا يُحذف أي مسار موجود قبل جرد وظيفته. لا تعرض الواجهة ميزة على أنها تعمل إذا كانت مجرد عنصر كتالوج أو Placeholder؛ تُوسم بوضوح بأنها قيد التطوير أو تُؤجل من الإصدار.

## 4. البنية التقنية المستهدفة

| الطبقة | Web | Android | قاعدة الاشتراك |
|---|---|---|---|
| واجهة المستخدم | React + TanStack Start الحالي | Kotlin + Jetpack Compose | تصميم وسلوك موحدان، تنفيذ أصلي لكل منصة |
| التنقل | Router الحالي + responsive drawer | Navigation Compose + modal drawer | أسماء الوجهات وعقودها متطابقة |
| التصميم | CSS tokens + مكونات React الحالية | Material 3 مخصص بألوان AbanoubAI | Design tokens موثقة |
| المصادقة | Supabase Auth بعد توحيد المشروع | Supabase Auth SDK / جلسة آمنة | نفس مشروع Auth ونفس هوية المستخدم |
| API | Server functions / endpoints موثقة | HTTPS API موثق | لا تستدعِ Android وظائف داخلية غير مستقرة |
| البيانات | Supabase + RLS | عبر API أو Supabase client محدود الصلاحية | ملكية المستخدم وفصل الصفوف |
| المهام | Durable server-side jobs عند توافرها | WorkManager للمهام المحلية المؤجلة | معرفات idempotency وحالة قابلة للاستئناف |
| المراقبة | سجل أحداث/أخطاء | Crash وnetwork state | لا تُسجل أسرارًا أو محتوى خاصًا افتراضيًا |

**قرار Android:** لا نعيد استخدام WebView كواجهة. نراجع PR #19 وخريطة المسارات الموجودة ثم نكمل نقلًا أصليًا تدريجيًا. مشروع Android الموجود فعليًا هو `android-companion/`؛ لا نفترض أن مجلد `android/` هو التطبيق.

**قرار PWA:** تُضاف manifest وأيقونات وservice worker/استراتيجية caching فقط بعد تحديد ما يجوز تخزينه. لا تُخزن المحادثات أو الرموز الحساسة في Cache عام. وضع offline يعرض آخر حالة محلية آمنة ورسالة اتصال واضحة، ولا يوهم بأن الطلب السحابي نُفذ.

## 8. تعريف الإنجاز والاختبارات

لا تُعد الشاشة مكتملة لمجرد ظهورها. لكل وجهة:
- بيانات صحيحة من مصدرها أو Empty state صريحة.
- أفعال تعمل فعليًا.
- Loading/error/offline/retry.
- RTL وDark/Light.
- Accessibility labels وtouch targets.
- صلاحيات مستخدم واختبارات ملكية.
- اختبار viewport صغير وواسع.

### مجموعة اختبارات الإصدار
1. Web: installability، responsive، auth، chat، tasks، route loading.
2. Android: native launch، لا WebView في المسار الرئيسي، auth persistence، drawer، chat، back navigation.
3. Cross-platform: نفس المستخدم يرى نفس المهام والمحادثات المسموح بها.
4. Security: unauthenticated denial، cross-user denial، JWT issuer mismatch، RLS، no client secrets.
5. Reliability: timeout، network loss، duplicate retry، app restart، resumable state.
6. Accessibility: contrast، dynamic font، TalkBack/keyboard، RTL.
7. Build: web build/lint/tests وAndroid unit/build من commit واحد معروف.

لا تُستخدم بيانات وهمية في مؤشرات الأداء أو حالات نجاح الوكلاء. لا يُقال "تم الاختبار على الهاتف" إلا بعد اختبار المستخدم على جهازه.

## 9. معايير قبول التصميم

- الهوية سوداء/فحمية وذهبية، فاخرة ومعاصرة، مستلهمة من المرجع الذي اعتمده المستخدم دون نسخ تفاصيل محمية.
- A فقط كأيقونة التطبيق.
- Home واحدة كوجهة افتراضية.
- كل الوجهات الأخرى في Sidebar/Drawer؛ لا Bottom Navigation.
- الويب والAndroid متشابهان في الهوية والبنية المعلوماتية، لكن كل منصة تستخدم مكوناتها المناسبة.
- غني بصريًا دون ازدحام: تسلسل بصري واضح، بطاقات محددة، ورسوم فقط عندما تضيف معلومة.
- Light mode يحافظ على الهوية ولا يتحول إلى قالب عام.
- كل شاشة عربية RTL، بما في ذلك ترتيب الأيقونات، اتجاه الحقول، القوائم والرسوم.
