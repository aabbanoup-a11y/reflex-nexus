# Product Agent v1

## طبقة التنفيذ

- `command-protocol.ts` يوحّد الأوامر الجديدة والقديمة.
- `command-executor.ts` يحوّلها إلى أوامر Companion الموجودة، أو يطلب إنشاء أداة عند غياب المحول.
- `continuation-memory.ts` يحفظ سياقًا شجريًا مختصرًا ويحدد ترتيب الاحتياطي المحلي.

## المصنوعات

- `artifact-manager.ts` يعرّف واجهة موحّدة للصورة والفيديو والمستند والكود.
- `product-agent.functions.ts` يسجل المصنوعات في Supabase.
- التوليد الفعلي يحتاج مزودًا رسميًا موصولًا؛ لا توجد مفاتيح API داخل الكود.
- موصل الفيديو الرسمي يجب تفعيله من بطاقة التفويض في بيئة Manus/المشروع؛ لا يتم اختراع API أو تخزين مفاتيح في GitHub.

## العمل دون إنترنت والجدولة

- Android يستطيع محليًا إرجاع حالة البطارية والشحن والشبكة والتخزين وAccessibility، وفهرس الملفات والإشعارات عند تفعيل صلاحياتها.
- `scheduler.ts` و`scheduled_jobs` يقدمان سجلًا آمنًا للمهام المجدولة؛ يحتاج التنفيذ الدوري إلى Cron/جدولة بيئة النشر حتى يشغّل التعليمات في موعدها.

## الحدود المقصودة

- Factory يكتب إلى `tools/` على فرع `ai-team` فقط، والنشر Cloudflare اختياري ومحصور في Worker endpoint الموجود.
- لا توجد صلاحية حذف شامل، تعديل مخطط Supabase تلقائيًا، أو نشر عام بلا مسار مراجعة.
- Jarvis overlay الحالي داخل التطبيق مع bridge للهاتف. Overlay فوق كل تطبيق يحتاج صلاحية Android SYSTEM_ALERT_WINDOW وتنفيذ Native، وليس ممكنًا من صفحة ويب وحدها.
- Secretary path يقرأ الرسائل فقط إذا وفر Companion أو موصل واتساب مصدرًا صريحًا؛ الرد الخارجي مغلق افتراضيًا حتى تفعيل الموصل.
